# OCI image materialization

Haven's `AdmitImageImport` defaults to `format=2`, `layout=layered-erofs-v1`, a real EROFS metadata image with ordered external block devices and shared per-`diff_id` data. Explicit `imageimport.ImageImportOptions.Materialization = host.MergedOCIEROFSLayout` (CLI `--materialization=merged-oci-erofs-v1`) selects the native umoci merged compatibility builder, published as `format=3`, `layout=merged-oci-erofs-v1`. The older `format=1`, `layout=merged-erofs-v1` remains separately verified and is never generated by either new builder. Existing catalog entries are not silently converted.

Each OCI digest has one immutable catalog identity. A request for a different materialization after publication returns `conflict`; the same selected layout can be imported again idempotently. There is no automatic fallback for unsupported metadata, digest/corruption errors, resource bounds or unsafe paths. A merged compatibility image does not claim shared layered materialization.

## Files and identities

Paths below are relative to the Haven state directory:

```text
layer-cache/<builder-hex>/<diff_id-hex>/layer.erofs
layer-cache/<builder-hex>/<diff_id-hex>/layer.json
images/<OCI-manifest-hex>/kernel
images/<OCI-manifest-hex>/initramfs
images/<OCI-manifest-hex>/fsmeta.erofs
images/<OCI-manifest-hex>/image.json
```

`Builder` is a sha256 identity over the materializer profile, exact `mkfs.erofs` / `fsck.erofs` version strings and the pinned, patched go-erofs dependency identity. The profile fixes block size, flags, deterministic layer UUIDs, timestamp handling, payload normalization, cached header encoding and host-tool execution semantics. Cache receipts include that profile and builder, `diff_id`, output sha256, validated uncompressed tar byte count and entry count. Changing tools or the profile selects a different cache directory. OCI compressed-layer descriptors remain ordered in `Layers`; `DiffIDs` records the corresponding uncompressed identities.

Previously published native-rebuild builders have no `Tools["go-erofs"]` entry. Their original profile, cache receipt checks and native UUID/tag/address-map verification remain supported. The new builder cannot reuse a legacy cache under its new key or reinterpret a legacy catalog entry as the new profile. Idempotent import verifies and returns an existing identity instead of rebuilding it with current tools.

`Files` contains exactly `kernel`, `initramfs` and `fsmeta.erofs`, with hashes. `Artifacts` contains fsmeta first, followed by one layer device per OCI layer, in bottom-to-top order. Each entry fixes role, state-relative path, output hash, device ID, VMM-visible path and serial. Layer entries also contain their `diff_id` and the hash of their cache receipt. Repeated `diff_id`s share the same cache inode but retain separate ordered device slots.

Layer publication uses a private pending directory, native fsck validation, readonly file modes, file/directory fsync, rename, and parent-directory fsync. An existing incomplete or corrupt cache is an error; import does not overwrite it. Image artifacts are likewise sealed and persisted before the SQLite image reference is published. Cache entries are reusable after their directory publication, even if the image import later fails. Catalog images and their referenced layer cache files remain retained. Haven's reference-aware GC can collect only caches and import work with original durable ownership/witness records; unknown/interrupted stages are preserved. See [the GC contract](engine-integration.md#reference-aware-garbage-collection). Reservations conservatively cover tar input, extraction, block padding and metadata, including already-cached inputs.

A new manifest referencing verified cached `diff_id`s can rebuild fsmeta and boot materials without source layer tar files. Manifest/config metadata still needs to be supplied and verified. Cache hits reuse the prior validation of the uncompressed tar identity and its supported semantics. They do not require a compressed blob to be available again. Cache byte and entry counts still count against each import's limits.

## Shared data pipeline

Both materializers use the same `host.ValidateLayer` preflight. `LayerInput` carries the file path, media type and expected uncompressed digest; `LayerLimits` carries the byte and entry bounds. Materialization mode does not select a weaker validation path.

`LayerCacheRequest` carries the validated layer, its byte/entry counts and exact builder into the corresponding shared or legacy cache builder. Both builders use one publication step for data hashing, receipt creation, sealing, file/directory fsync and rename. `FsmetaLayers` keeps ordered external devices with their state root and private output directory; each materializer retains its own explicit builder or manifest identity. These internal values do not change receipts, builder profiles or published image formats.

`imageimport.ImportWork` carries the original operation, frozen plan and prepared directory identities through staging, layer materialization and output construction. Haven separately verifies publication authority before choosing either published-work cleanup, which owns only inputs, or unpublished-work cleanup, which also checks the original output inode. The two cleanup entrypoints do not accept a publication-mode flag.

The layered materializer requires matching erofs-utils versions **>=1.9.4 and <2**. The implementation has been exercised with erofs-utils 1.9.4. Loom uses the public Writer API of [go-erofs](../third_party/go-erofs/UPSTREAM.md) for per-image metadata composition.

For each missing layer, preflight validates canonical sha256 descriptors, compressed-blob checksum and size, the complete uncompressed tar digest, decompression/entry bounds and supported metadata. Normalization writes a private tar with every regular entry version at an indexed `data/<entry-index>` name. Overwritten versions stay available because another hardlink may still refer to their inode. Original headers and OCI operations are encoded with standard `encoding/gob` as `headers.gob` in the same cache EROFS. Attribute maps are sorted before encoding; arbitrary binary capability/ACL values retain their bytes. The cache hash authenticates this index along with all payloads. Cached index decoding bounds its size using the authenticated receipt, checks entry counts and attribute ordering, revalidates headers and refuses trailing data.

Native conversion invokes the host executables directly in a private work directory:

```text
mkfs.erofs --workers=1 --tar=f -b4096 -E noinline_data \
  -T0 --mkfs-time --preserve-mtime -U <diff_id-derived-UUID> \
  layer.erofs payload.tar
fsck.erofs --extract layer.erofs
```

`--tar=f` stores actual file data; `noinline_data` keeps every regular payload in native FLAT_PLAIN extents. Whiteouts and unresolved hardlinks remain operations in the index, so independent cache construction never needs a lower layer or future target. The temporary tar is removed before immutable publication. Archive paths are not extracted onto the host.

For each image, Loom opens these verified caches in OCI bottom-to-top order. A metadata-only `fs.FS` adapter exposes payload extents to go-erofs `CopyFrom(..., MetadataOnly())`; its `Open` method deliberately refuses file reads. Public `Link`, `RemoveAll`, `Mkdir`, `Chown`, `Chtimes` and xattr APIs compose the final namespace. Each cache contributes one ordered external device. Regular payloads remain in shared cache files; only directory/symlink/xattr/chunk-reference metadata is written to fsmeta. The dependency owns all EROFS inode, directory, xattr, device-table and chunk serialization.

The pinned dependency is `v0.3.3-0.20261101155608-4c135619312a`, with a documented one-line fix to its device-table offset calculation. Its patched identity ends in `+sandbox-devtable-v1` and participates in the builder hash. Loom never patches emitted filesystem bytes. See [dependency provenance](../third_party/go-erofs/UPSTREAM.md) for the commit, license and patch.

The importer strictly validates superblock features, actual layer UUIDs, ordered slot counts and block geometry. This library profile emits explicit chunk device IDs with zero fsmeta UUID/device tags and zero concatenated mapped addresses; the manifest hashes, authenticated receipts and ordered bindings fix device identity. The older native-rebuild profile retains its distinct UUID-tag and concatenated-address checks. Neither profile accepts the other's geometry.

Native fsck reads/extracts the final filesystem through all supplied external devices into a private directory. Root-confined path checks enforce required boot files, systemd and agent materials; kernel/initramfs are copied from that final view. This temporary extraction is not published as the read-only lower. There is no per-image merged regular-data filesystem.

`-T0` alone defaults to applying that timestamp to every file. `--preserve-mtime` by itself does not undo that policy. `--mkfs-time` is required to preserve input file mtimes while fixing the native build timestamp; the library also receives a fixed build timestamp and explicit inode times.

Shared composition preserves numeric OCI ownership directly in EROFS metadata. Basic layered conversion needs no host chown, mounts or device creation. Full native extraction tests for ownership, ACLs and capabilities require the corresponding host privileges.

## Host tool installation

Executables are selected through an administrator-controlled PATH and resolved before execution. Each child receives a private work directory, the host-tool PATH and `LC_ALL=C`. Runtime libraries use the normal host installation; there is no tool-root projection or package-manager-specific path setting.

Tools run with the caller's host authority. Private directories separate import artifacts; they do not sandbox the tool process. Image paths never select executables, and image executables are never invoked. The shared profile `erofs-shared-oci-v2;host-tools` and merged profile `umoci-native-merged-v3` give this execution policy distinct builder/cache identities.

## Explicit OCI merged compatibility

The compatibility builder requires umoci **0.6.0**, matching erofs-utils **>=1.9.4 and <2**, and effective UID 0 to preserve native ownership. Its builder sha256 includes a distinct profile plus exact version output for umoci, mkfs and fsck. That profile fixes native unpacking, private-directory extraction, block size, native xattrs, flags, UUID and timestamp policy. It does not use the layered cache or its receipts.

Every layer is staged and checked before unpacking: compressed checksum and descriptor size, full uncompressed `diff_id`, tar/decompression/entry bounds, safe archive and hardlink paths, allowed entry types, whiteout shape, metadata ranges, xattr names and PAX records. Config descriptor size is checked too. Aggregate compressed descriptors are bounded to twice the uncompressed import budget, metadata blobs to 16 MiB each. A trusted minimal OCI index selects only the verified manifest; source indexes, tags, URLs and annotations cannot redirect unpacking.

The importer creates a private `.unpack-*` directory under its pending output directory. umoci runs with a child-only `umask=077`; mkfs then reads that same native tree. The unpack directory is removed before boot extraction and publication, including cleanup on failure. No namespace, subordinate-ID helper or tmpfs mount is involved.

The trusted pipeline uses actual host paths:

```text
umoci raw unpack --image <verified-layout>:compat <private-unpack>/root
mkfs.erofs --workers=1 -b4096 -E noinline_data -T0 --mkfs-time \
  --preserve-mtime -U <manifest-derived-UUID> <pending>/root.erofs <private-unpack>/root
```

`umoci --rootless` is deliberately absent. UID/GID, setuid/setgid/sticky bits, nanosecond mtimes, hardlink identity, xattrs, ACLs and capabilities are represented as native filesystem metadata. Invalid Linux ownership/ACL IDs, unavailable xattr support, insufficient disk space and native unpack failures abort import; metadata is never silently replaced by synthetic ownership xattrs. Tar byte/entry bounds and Haven reservations remain enforced; extraction consumes the caller's backing filesystem under its host resource limits.

Native fsck checks/extracts the resulting self-contained filesystem in a separate private work directory. The shared confined boot contract checks and `os.OpenRoot` copy kernel/initramfs from that final EROFS view. Immutable publication uses the same seal/fsync/rename/catalog ordering as the layered path. The layout has exactly `{kernel,initramfs,root.erofs}` in `Files`, no external `Artifacts`, ordered original `Layers`/`DiffIDs`, and the distinct builder/tools. `Verify` checks this identity, readonly regular nonsymlink artifacts, hashes, platform, EROFS geometry, UUID and absence of external data devices.

Compatibility handles arbitrary supported root attributes, inherited directories without repeated parent headers, cross-layer regular and symlink hardlinks to existing targets, root/nonroot opaque markers, whiteouts and same-layer replacement in either order, duplicate path replacement and PAX metadata. It retains the 1..16 OCI layer input bound. All source layer blobs are required for a new compatibility publication; only the layered path offers cache-only fsmeta rebuild. No conversion between these immutable layouts occurs.

True forward hardlinks whose target does not yet exist remain an explicit native-tool limitation: umoci 0.6.0 fails with `unpack entry: ...: link: no such file or directory` and no image is published. A hardlink to an existing lower inode followed by replacement of its target name correctly retains the earlier inode. Directory hardlinks are refused by native Linux extraction. Special files, zstd, unknown PAX attributes, unsupported xattr namespaces, negative/out-of-range metadata and Linux symlink modes other than 0777 remain refused.

## Runtime integration contract

Call `m.ReadOnlyBindings(imageDir)` before using artifacts. It calls `Verify` and returns ordered `[]ImageBinding` with absolute `HostPath`, `GuestPath`, `Serial`, `SHA256`, `Role`, `DiffID` and `DeviceID`. `imageDir` must be the absolute `images/<manifest-hex>` directory. Hosts must bind each file readonly, attach it as a readonly raw block device, and prevent access to another writable path to its inode.

| Role | Device ID | Stable VMM path | Serial |
| --- | --- | --- | --- |
| fsmeta | 0 | `/sandbox/ro/fsmeta.erofs` | `sandbox-root` |
| first data layer | 1 | `/sandbox/ro/data-0000.erofs` | `sandbox-data-0000` |
| next data layers | 2..16 | `/sandbox/ro/data-0001.erofs` .. `/sandbox/ro/data-0015.erofs` | `sandbox-data-0001` .. `sandbox-data-0015` |

`MaxImageDataDevices` is 16 external layer backends; fsmeta and the writable upper disk are additional devices. Imports with more layers are explicitly rejected, including repeated layers. `m.DataSerials()` returns the comma-separated ordered data serials; `m.DataKernelParameter()` returns the complete `sandbox.data_serials=...` argument. These helpers validate manifest structure; `ReadOnlyBindings` verifies the actual files and caches too.

Initramfs must resolve devices by serial and mount the fsmeta block device with ordered `device=<resolved-data-device>` options. Never infer layer identity from `/dev/vd*` enumeration. Snapshots must retain this layout, complete manifest and ordered immutable device paths. Both explicit merged layouts return the single `/images/root.erofs` binding with `sandbox-root` serial and an empty data-serial parameter. Format 3 validates its distinct builder and file identity before returning those bindings.

`Verify` rejects wrong layout/format/platform/builder, missing/extra/reordered artifact entries, wrong paths/serials/device IDs, file and receipt hash mismatches, missing or writable artifacts, symlink files or cache directories, incorrect device-table tags/block maps, unsupported format features, and empty/non-EROFS metadata images. It reads artifact bytes without invoking external tools. Full native inode/content validation happens before publication. Local private state and SQLite/catalog integrity remain the trust boundary; hashes are integrity checks, not signatures against a host administrator who rewrites the catalog and every artifact.

Cloud Hypervisor disk wiring, launcher mount bindings, saved-layout validation and the guest mount path use this manifest contract. The standalone guest image test attaches the full ordered set and boots the actual guest for both layouts.

## OCI namespace semantics and limits

The default shared builder preserves supported root metadata, regular files, directories, symlinks, numeric UID/GID, setuid/setgid/sticky permissions, nanosecond mtimes and native xattrs. Both builders allow `user.*` excluding `user.overlay.*`, `security.capability`, and POSIX ACL access/default attributes. Unknown PAX attributes and unsupported xattr namespaces fail explicitly. Actual native extraction tests validate root/directory attributes, v2/v3 capabilities and named-user ACL bytes.

The shared namespace composer handles:

- Same-layer and cross-layer regular/symlink hardlinks, including true forward chains. Deferred links resolve as soon as the target inode appears. Later replacement of its target name preserves that earlier inode through surviving aliases. A later entry replacing a pending alias or its ancestor directory cancels that pending name. Cyclic/unresolved links and directory hardlinks fail before publication.
- Root and nonroot opaque markers and regular-file whiteouts. All whiteouts apply to the preceding layer view before ordinary current-layer entries, so replacement works in either tar order and root opaque retains same-layer children.
- Implicit parents and inherited existing directories. The shared profile deterministically assigns missing parents the owner, permission and timestamp of their nearest existing parent until an explicit directory header replaces those attributes. Existing directory metadata survives layers that add only children. This policy is specific to the shared profile: the explicit umoci builder creates implicit parents under its fixed `umask=077`, which can produce mode 0700.
- Duplicate path replacement, including directory-to-file and file-to-directory replacement. Explicit directory metadata updates retain existing children. Path traversal through a symlink or other nondirectory is refused; guest symlink targets themselves may be absolute.

Special devices/FIFOs, zstd layers, unknown PAX attributes, unsupported xattr namespaces, negative/out-of-range metadata, Linux symlink modes other than 0777 and more than 16 layer devices remain refused. The explicit umoci builder additionally refuses true forward hardlinks and metadata that the host cannot represent. These limits are checked explicitly and do not trigger another materialization mode.

The older native-rebuild profile remains frozen for existing catalog verification. Its native tar conversion required explicit parents and backward same-layer regular hardlinks; rebuild synthesized its root and could not express the broader cases above. In erofs-utils 1.9.4, `lib/tar.c` requires a hardlink target already in the current tar tree, while `lib/rebuild.c` walks source root children without importing root inode metadata. The new profile uses public library composition to remove those namespace restrictions while preserving native shared payload storage.

Native source research used the Nix-pinned erofs-utils 1.9.4 archive (sha256 `7d135aa2550326a5acf20f53c518aea5a8900015ce50700044e40f818c31dd80`), especially `man/mkfs.erofs.1`, `mkfs/main.c`, `lib/rebuild.c`, `lib/tar.c`, `lib/inode.c` and `lib/super.c`. The pinned library source and local patch are recorded separately in [UPSTREAM.md](../third_party/go-erofs/UPSTREAM.md).

## Validation

Tests use the caller's prepared toolchain under the same contract for every
environment provider. `just test` is the quick entrypoint and may skip native
tests for missing tools or privileges. `just test-native` forces `SANDBOX_REQUIRE_EROFS_TESTS=1` and runs every host workspace module independently
with `-json -race ./... -count=1 -timeout=300s`;
missing prerequisites fail, and stdout contains only Go JSON. The required native
pass events come from `github.com/woxQAQ/haven/image` for materialization and
`github.com/woxQAQ/haven/gc` for cache reclamation.

The gate additionally checks the original command exit code and individual
pass events for `TestActualLayeredEROFSImportAndExtraction`,
`TestActualSharedOCIHardlinksAndMetadata`,
`TestActualMergedOCIHardlinksAndMetadata`, and
`TestGCActualLayerCacheAndCompletedImport`. A package pass alone is insufficient.
It rejects non-JSON output and skipped native tests (`TestHavenActual*`, `TestActual*`,
`TestGCActual*`, `TestLayerValidation*`, `TestLegacyNativeLayered*`,
`TestSharedCached*`, `TestMergedOCI*`), with no ownership skip exception. Other skips,
including package skips for packages without tests and unrelated guest image or capture
tests, are recorded separately in `skips.json` and do not supply native coverage.

Prepare Go with race/C compiler support, just, git, Python >=3.11, coreutils,
golangci-lint, matching mkfs/fsck.erofs **>=1.9.4 and <2**, dump.erofs and umoci
**0.6.0**. Full merged/metadata validation requires effective UID 0 and host
ownership/xattr support. Executable realpaths and versions are retained as evidence.
No namespace or subordinate-ID mapping preparation is required.

```sh
python3 scripts/check-native-gate.py --negative
python3 scripts/check-native-gate.py
```

Use a newly created private temporary root for test state. Unix listeners
and guest transports support long runtime directories through anchored parent
FDs; filesystem ownership and explicit inode cleanup remain verified. A short
private tmpfs is convenient for large SQLite/resource fixtures, independently of
the JSON/race/300s gate semantics.

`--negative` retains the normal compiler/base-tool PATH projection except
for mkfs.erofs, then actually runs the single required layered test. Success means
the child failed and emitted the exact `required OCI tool missing: mkfs.erofs`
test diagnostic, not a compiler error or some other missing tool. The view is
private to that command and removed on normal success or failure.

On a **prepared, disposable root CI runner**, also run:

```sh
python3 scripts/check-native-gate.py --preflight
```

Preflight checks effective UID, versions and actual executable paths, then runs
`TestActualMergedOCIExplicitSelectionAndVerification` through the Loom
host-tool helper. Full shared/merged coverage still comes from the complete gate.
Preflight never switches identity or changes host policy.

The GitHub `native-image` job uses Ubuntu 24.04, source-pinned erofs-utils
1.9.4, umoci 0.6.0, golangci-lint 2.14.0,
and distribution Python/coreutils. The gate uses only Python's standard
library; Nushell is neither installed nor invoked.
Separate preparation steps install tools;
the official `golangci/golangci-lint-action@v9.3.0` supplies the fixed lint version
using `install-only`, and the existing `just lint` remains the single lint entrypoint.
Lint runs without sudo after native validation, so its `go fix` cannot rewrite the
checkout before the native tests. The native probes/tests receive only
the controlled PATH and `GOTOOLCHAIN=local` through `sudo env -i`. The gate
creates private runtime HOME when none is supplied, rather than forwarding
runner credentials. Cache keys include workflow/tool-source identity, Go
module sums and Cargo.lock; restored caches never bypass the gate.
The cache identity is computed before privileged tests and reused verbatim in
the cache post step, so hashing never traverses root-owned private runtime HOME.

Each invocation retains separate stdout/stderr/exit-code files, source
revision, entrypoint hashes and its verdict in a fresh, gitignored
`build/native-gate/run.*` directory. The CI artifact allowlist includes only
diagnostic files, not private runtime HOME, PATH views, databases, tokens or
the full environment. Its results cover native host materialization and GC. Committed
workflow configuration is not evidence that GitHub has executed it.

`python3 -I scripts/test_native_gate.py` exercises the public gate CLI in private
workspaces with a closed fixture PATH, without Nushell or privileges. It checks
raw logs/statuses, exact pass/skip/failure rules, negative PATH cleanup and a
clean runtime HOME.

Actual shared tool tests import gzip/uncompressed OCI fixtures, read the final external-device filesystem with native fsck, inspect chunk layout and UID/GID using native dump, and verify file contents, reversed layer order, boot extraction, repeated layers and the 16-device boundary. Broader namespace regressions cover root ownership/mode/xattrs/nanosecond time, inherited directories, implicit parents, cross-layer and symlink inode identity, forward chains, old inode retention through duplicate replacement, overwritten pending links, ancestor replacement, root/nonroot opaque, whiteout/replacement in either order, setuid/setgid, native v2/v3 capabilities and named-user ACLs. Cache-only rebuild repeats forward-link content checks after deleting original tar blobs. Independent imports compare complete output hashes for determinism. A legacy-native fixture is built with the frozen old profile, verified and reimported from its existing catalog unchanged.

Integrity tests cover cache corruption/missing receipts, manifest order/hash/profile checks and unsafe artifact paths. Invalid namespace tests ensure unresolved/cyclic/directory hardlinks and symlink-parent traversal publish no catalog entry. GC tests also exercise actual default imports. Rejection tests document limits; they do not establish support for those inputs.

Additional actual umoci tests exercise its separate merged layout, including root attributes, cross-layer links, capabilities/ACLs, whiteout and duplicate ordering, symlink confinement, boot symlink refusal, digest/descriptor/resource limits, invalid ownership, immutable manifests and layout conflicts. Its forward-hardlink refusal checks that no catalog entry is published.

`just guest-image-e2e` boots both layouts with the pinned VMM, matching kernel and packaged guest. It checks serial-based EROFS mounts, initramfs handoff to systemd, file metadata, links, xattrs, ACLs, capabilities and rejection of writes through readonly devices. Guest-agent tree transfer, retained private RAM and a second snapshot restore exercise the running guest across generations. See [runner inputs](../scripts/README.md#vm-test-inputs) and [historical test results](verification-history.md).
