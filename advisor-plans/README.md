## Findings considered and rejected

- `loom/*_deletion_linux.go` family: already symmetric (same `InspectX` shape,
  same proof-verification order). Not a finding.
- `haven/sandbox/lifecycle_{pause,resume,restore,release,checkpoint,rollback}.go`:
  already symmetric file naming. Not a finding.
- `machine.VMGuards` shared by several services while others have dedicated
  `XGuards`: the dedicated interfaces embed `VMGuards` and add one
  resource-scoped guard, so the two granularities are deliberate. Not a finding.
- `StopInput` fields lacking JSON tags while `CaptureInput` fields have them:
  real asymmetry, but `StopInput` is frozen into persisted operation envelopes
  and adding tags would change `InputHash` for future operations; requires a
  hash-migration analysis that is out of scope for a symmetry pass. Revisit
  deliberately, not as a rename.
- Moving `loom/config.CLI` next to `cmd/loomctl` (mirroring havenctl's local
  settings): rejected — README documents "`haven/config` and `loom/config`
  contain their respective settings"; placement is a documented decision.
- `havenctl` keeping its `settings` struct in `sdk/cmd/havenctl`: no documented
  `sdk/config` package exists; left as-is (see 007 for what is unified instead).
